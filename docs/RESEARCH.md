## Reproducible version pins

* Pi OS current swap manager: [rpi-swap](https://github.com/raspberrypi/rpi-swap), using a pure-zram drop-in without SD writeback. Do not run zram-tools alongside it.
* HA image: `ghcr.io/home-assistant/home-assistant:2026.9.4` (ARM64). A version tag, not `stable/latest`; manifest lookup confirmed `linux/arm64` and `linux/amd64`. Index digest observed: `sha256:3e6710a7ab2a61311d9d899b719f6c3657791c63e8f4942cec4ebc42401d6b76`; record the resolved image digest on the Pi for rollback assurance.
* BLUETTI v1.0.5: `f1df72b9642ebb60cb1c56100f2ad3c3a5b60157`.
* Meshtastic v0.6.1: `b641e747c17dc03aec3ef4d020b6573bff3d71d1`; camper patches force PKI replies, disable host clock/timezone writes to the GPS radio and cosmetic Internet lookup, and pin protobuf/aiomqtt requirements to HA constraints. See [MESHTASTIC](MESHTASTIC.md) for source links/security/commissioning. Main and v0.6.2 release candidates are deliberately not installed.
* BMS_BLE-HA 2.17.0: `23ba216aea103220be2fc66ba3fe21092391219b`; `aiobmsble==0.28.0`.
* BLUETTI native BLE library release date: `20260908`. The vendor release marks ARM64 musl/Python 3.14 **untested on physical equipment**. The corresponding library URL returned HTTP 200 during research; availability alone is not ABI/device validation.

The installer checks full source commit SHA after fetching a release tag. It does not vendor dependencies or publish downloaded native libraries. Pi OS/Docker packages come from signed APT repositories at installation time; their exact versions should be saved privately using `dpkg-query -W`.

## Coexistence and unresolved questions

Wi-Fi and Bluetooth share 2.4 GHz airtime and an onboard radio assembly. HA documents interference and potentially long connection times on slower adapters; the Zero 2 W is not established here as a tested high-performance three-device BLE host. There is no evidence that an undocumented firmware parameter fixes all coexistence problems. Start at BLUETTI 30–60 s polling, BMS default 30 s, Aranet default cadence; close vendor phone apps. Verify concurrent BLE and Wi-Fi switching, including cold boots. Do not enable a second scanner or continuously run `bluetoothctl scan on`.

Unknowns requiring the real hardware: exact Elite firmware/entity list, valid BLE key lifetime, native library import on ARM64, BMS subtype/firmware, AP firmware behaviour, Android app mDNS/mobile-data routing, actual memory use and thermal/power stability.

Meshtastic adds a fourth BLE device: a persistent connection to the dedicated T1000-E, not another scanner. The two portable radios use their own phones. Stable v0.6.1 imports under HA 2026.9.4 but uses deprecated pyserial-asyncio (HA removal scheduled 2027.2) and a unit constant (2027.8); review upstream compatibility before any HA version update. Test actual firmware PKI metadata, GPS LOC_INTERNAL and pairing/reconnect locally. ADS-B and receiver-location feed updates remain deferred; no SDR service is installed.
