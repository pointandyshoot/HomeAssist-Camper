# Future fridge/freezer receiver

The OTG USB port has no Wi-Fi/BLE dependency. Existing BLE integration and HA Compose layout remain in place when an RTL-SDR is added.

The simplest ARM64 extension is Raspberry Pi OS's `rtl-433`/`rtl-sdr` packages and a host systemd service. [Upstream rtl_433](https://github.com/merbanan/rtl_433) also supports building its C/CMake source with libusb/librtlsdr on ARM64. Use native packages first; confirm the current distro package/receiver support while online. Don't assume an arbitrary Docker image has ARM64 builds.

Future path: **RTL-SDR → rtl_433 → local MQTT → native HA MQTT**. Add one small Mosquitto container/service only when the receiver exists; use local authenticated MQTT and store credentials in private files. Match supported sensor protocols/IDs before deploying HA discovery. Plain rtl_433 MQTT output is not itself a promise that discovery is configured: use a reviewed discovery bridge or explicit HA MQTT sensor definitions.

Commissioning sequence:

1. Check receiver power and kernel driver claims. Many tuners are captured by DVB drivers; blacklist the relevant DVB module only when needed, then reboot. Use udev least-privilege device permissions for the service; avoid permanently running a receiver as root.
2. Install `rtl-433 rtl-sdr`, inspect `rtl_test` and run `rtl_433 -f 433.92M -F json` interactively. Capture actual sensor frames privately, with temperatures in °C. Confirm exact decoder protocol and false-positive behaviour.
3. Configure a restricted decoder list and MQTT output locally using [upstream output documentation](https://triq.org/rtl_433/OPERATION.html). Keep receiver IDs and MQTT credentials out of the public repo.
4. Add the local broker/receiver service and HA native MQTT configuration. Use availability/expiry; an old sensor value is not proof a fridge is still cold. Battery-powered temperature transmitters may report infrequently.
5. Map `sensor.camper_fridge_temperature`/`sensor.camper_freezer_temperature`, replace the dashboard placeholder and add 12 h temperature graphs. Validate calibration and packet gaps.
6. Run resource/BLE/Wi-Fi and offline-reboot tests again. RTL-SDR power draw, decoding CPU use and extra MQTT memory must fit the Pi; these are not included in initial acceptance.

This stage intentionally contains a plan, not a fabricated sensor protocol/config. No USB dongle, broker or rtl_433 daemon is installed yet. If more USB power is required later, a powered OTG hub for the receiver is possible; it does not become a Wi-Fi/BLE requirement.
